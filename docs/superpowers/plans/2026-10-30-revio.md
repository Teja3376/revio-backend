# Revio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Revio, an AI code reviewer with one shared engine and three front-ends (npm CLI, VS Code extension, GitHub App with a NestJS + Next.js web app).

**Architecture:** A pnpm + Turborepo monorepo. `packages/core` turns a unified diff into validated `Issue[]` via Gemini. CLI and extension call core directly with the user's key. `apps/api` (NestJS) receives GitHub webhooks, queues reviews with pg-boss, runs core at full depth, posts PR reviews, and stores small review records in Supabase via TypeORM. `apps/web` (Next.js) shows repos, settings and review history.

**Tech Stack:** TypeScript (strict), Node 20+, pnpm, Turborepo, vitest, Biome, tsup, zod, `@google/genai`, picomatch, commander, chokidar, picocolors, VS Code API + esbuild + vsce, NestJS, TypeORM, Supabase Postgres, pg-boss, Octokit, Next.js App Router, Tailwind, shadcn/ui, TanStack Query, Supabase Auth.

**Spec:** `docs/superpowers/specs/2026-10-30-revio-design.md`

**Detail level:** Phases 0–1 are fully specified. Phases 2–4 are listed at task level and get a detailed plan of their own before they start, written against the real code from Phases 0–1.

## Global Constraints

- Node >= 20, TypeScript `strict: true`, ESM everywhere except the VS Code extension bundle (CJS via esbuild).
- Depths: `quick` = bug, security · `normal` = + performance, quality · `full` = + style, summary, risk.
- Models: Flash for quick/normal, Pro for full; exact IDs verified against Google's docs at build time and kept in one constant `DEFAULT_MODELS` in core.
- AI output is always zod-validated. On invalid output: retry once, then return `{ issues: [] }` plus a warning. Raw model errors never reach the user.
- Issues on lines that are not added/changed in the diff are dropped.
- Diff cap: ~2,000 changed lines per Gemini request; larger diffs are reviewed in per-file batches.
- Default ignores: lockfiles (`**/pnpm-lock.yaml`, `**/package-lock.json`, `**/yarn.lock`), `**/dist/**`, `**/build/**`, `**/*.min.*`, `**/*.map`, binary files.
- Never store source code or diffs in the database.
- No real network calls in tests; Gemini and GitHub are always mocked.
- Secrets only via env / VS Code SecretStorage; every app ships a `.env.example`.
- GitHub App is public, runs on the owner's Gemini key, with a daily cap per installation (env `REVIEW_DAILY_CAP`, default 50).
- CLI exit codes: 0 ok · 1 issues at or above block level · 2 usage/config/API error.

## Review Focus

- **No changes / empty diff:** `revio review` on a clean tree prints "No changes to review." and exits 0, without calling Gemini. → Task 4 (`review` short-circuit) and Task 7.
- **Deleted, renamed and binary files in the diff:** these never produce issues and never crash the parser. → Task 2 tests.
- **Gemini failures (429, timeout, network down, bad key):** the CLI prints one readable line and exits 2; the watcher keeps running. → Task 4 (`ReviewError`) and Tasks 7–8.
- **Not a git repo / git not installed:** the CLI prints "Revio needs a git repository" and exits 2. → Task 6.
- **Duplicate webhook deliveries and force-pushes:** the same head SHA is never reviewed twice; a failed compare falls back to the full PR diff. → Task 18 (detailed in the Phase 3 plan).

### Task 2: Diff parser

**Files:** Create `packages/core/package.json`, `packages/core/src/diff.ts` · Test `packages/core/src/diff.test.ts` (fixtures in `packages/core/test/fixtures/*.diff`)

**Interfaces:**
- Produces: `type FileDiff = { path: string; status: 'added' | 'modified' | 'deleted' | 'renamed'; binary: boolean; addedLines: number[]; patch: string }` and `parseDiff(diff: string): FileDiff[]`. `addedLines` holds new-file line numbers of `+` lines; `patch` is that file's raw section.

- [ ] **Step 1: Write failing tests:**
  - `modified.diff` with one hunk `@@ -10,3 +10,4 @@` adding 1 line at new line 11 → `[{ path: 'src/a.ts', status: 'modified', addedLines: [11] }]`
  - two files in one diff → two entries, in order
  - `deleted.diff` → `status: 'deleted'`, `addedLines: []`
  - `renamed.diff` (`rename from`/`rename to`, no hunks) → `path` = new name, `status: 'renamed'`, `addedLines: []`
  - `binary.diff` (`Binary files ... differ`) → `binary: true`, `addedLines: []`
  - `''` → `[]`
- [ ] **Step 2:** Run `pnpm --filter @revio/core test diff`. Expected: FAIL.
- [ ] **Step 3:** Implement `parseDiff` with a line-by-line state machine (no dependency): track `+++ b/` paths, `@@ +start` counters; `+` increments and records, ` ` increments, `-` doesn't.
- [ ] **Step 4:** Run the tests. Expected: PASS.
- [ ] **Step 5:** Commit `feat(core): unified diff parser`.

### Task 4: Review engine (prompt, model client, validation)

**Files:** Create `packages/core/src/prompt.ts`, `model.ts`, `review.ts`, `index.ts` · Test `packages/core/src/review.test.ts`

**Interfaces:**
- Consumes: Tasks 1–3
- Produces:
  ```ts
  interface ModelClient { generate(req: { model: string; prompt: string; jsonSchema: object }): Promise<string> }
  createGeminiClient(apiKey: string): ModelClient          // @google/genai, responseMimeType 'application/json' + responseSchema
  DEFAULT_MODELS: Record<Depth, string>                   // verify IDs at build time
  class ReviewError extends Error { kind: 'auth' | 'rate_limit' | 'network' | 'unknown' }
  ```

- [ ] **Step 1: Write failing tests** using a fake `ModelClient`:

  - valid JSON with one issue on an added line → returned

  - `generate` throws a 429-like error → rejects with `ReviewError` of `kind: 'rate_limit'` (401/403 → `'auth'`; fetch failure → `'network'`)

- [ ] **Step 5:** Add `packages/core/scripts/smoke.ts` (reads `GEMINI_API_KEY`, reviews a fixture with a planted `==` password compare, prints the result). Run it manually once and confirm it reports the planted bug. This also confirms the `DEFAULT_MODELS` IDs.

## Phase 2: VS Code extension (detailed plan written before starting)

- **Task 11: Extension scaffold + API key.** `packages/vscode` with esbuild CJS bundle, activation on `workspaceContains:.git`, "Revio: Set Gemini API Key" storing the key in `SecretStorage`, and settings `revio.enabled` and `revio.depth` (default `normal`). Tests via `@vscode/test-electron`.
- **Task 12: Commit detection.** Use the `vscode.git` API; on `repository.state.onDidChange`, when `HEAD.commit` changes, diff `HEAD~1..HEAD` (first commit: against the empty tree; merges: first parent). Status bar spinner while reviewing; never a modal.
- **Task 13: Diagnostics + quick fix.** `DiagnosticCollection('revio')` mapping severity; a `CodeActionProvider` "Apply Revio fix" replacing `line..endLine` with `suggestion`; clear a file's diagnostics on its first edit. Commands: "Revio: Review Last Commit", "Revio: Clear Issues".
- **Task 14: Package and publish.** `vsce package`, a Marketplace publisher (Azure DevOps PAT), icon and README, a release workflow.

## Phase 3: GitHub App + backend + frontend (detailed plan written before starting)

- **Task 15: API scaffold.** NestJS app in `apps/api`; TypeORM to Supabase Postgres (`DATABASE_URL`), entities `users, installations, user_installations, repos, reviews, review_issues` as in spec §4.4, initial migration, `synchronize: false`, Swagger at `/docs`, `.env.example`, local Supabase via the Supabase CLI.
- **Task 16: Webhook endpoint.** `POST /webhooks/github` on the raw body, `X-Hub-Signature-256` HMAC verified in constant time (401 otherwise), respond 200 quickly, enqueue a pg-boss `review-pr` job for `pull_request` opened/synchronize/reopened/ready_for_review.
- **Task 17: Installation sync.** Handle `installation` and `installation_repositories` events to upsert/delete installations and repos.
- **Task 18: Review worker.** Skip drafts and disabled repos; daily cap per installation (`REVIEW_DAILY_CAP`=50, then a "daily limit reached" comment); dedupe on unique `(repo_id, pr_number, head_sha)`; diff = full PR diff first time, then compare `last_reviewed_sha...head_sha` with fallback to the full diff; config = dashboard settings + `.revio.json` from the **base** branch (dashboard wins); `core.review` at full depth; post one GitHub review with inline comments on changed lines; create or update a single summary comment (marked with a hidden HTML comment); persist the review + issues; 3 retries with backoff; status `failed` + error on final failure.
- **Task 19: Auth + REST.** Supabase JWT guard; `POST /auth/link` taking the GitHub provider token once and storing `user_installations` (token not kept); `GET /me`, `GET /repos`, `PATCH /repos/:id`, `GET /reviews`, `GET /reviews/:id`, all scoped to the user's installations.
- **Task 20: Web scaffold + landing.** Next.js App Router in `apps/web`, Tailwind + shadcn/ui, TanStack Query, Supabase Auth with the GitHub provider (configured with the GitHub App's client id/secret), landing page `/`.
- **Task 21: Repos page.** `/repos` with an install-app link, an enable switch, depth and ignore-glob settings.
- **Task 22: Reviews + settings pages.** `/reviews` list with pagination, `/reviews/[id]` issues grouped by file with a PR link, `/settings` with sign out.

Revio Build Plan

One shared review engine powering three tools: a CLI that reviews quietly while you code, a VS Code extension that reviews each commit, and a GitHub App that reviews pull requests. Built in five phases, and each phase ships something you can use.

Phase 0

Foundation: the shared review engine

The monorepo and packages/core, which turns a git diff into a validated list of issues using Gemini.

TypeScriptNode 20+pnpmTurborepo@google/genaizodpicomatchvitestBiomeGitHub Actions
  1. Task 1

    Monorepo scaffold + shared types

    Workspace, CI, and the Issue / Depth / Config types with zod schemas.

  2. Task 2

    Diff parser

    Reads git diffs: changed line numbers per file; handles deleted, renamed and binary files.

  3. Task 3

    File filtering + depth categories

    Skips lockfiles, build output and your ignore list, and decides what each depth checks.

  4. Task 4

    Review engine

    Prompt, Gemini call, JSON validation, one retry on bad output, splitting large diffs, dropping issues on unchanged lines.

  5. Task 5

    Config loading

    Reads .revio.json and gives clear errors when it's wrong.

DONE WHENa diff goes in and a clean list of issues comes out, fully tested.

You'll need: Gemini API key.

Phase 1

CLI: the npm package

Quiet reviews in the terminal. It prints only when it finds something.

commanderchokidargit (execFile)picocolorstsupchangesets
  1. Task 6

    Git helpers

    Working-tree, staged and branch diffs, including new untracked files and repos with no commits yet.

  2. Task 7

    revio review

    On-demand review with readable output and exit codes: 0 ok, 1 blocking issues, 2 errors.

  3. Task 8

    revio watch

    Reviews on save after a 2-second pause, skips unchanged diffs, and keeps running if Gemini fails.

  4. Task 9

    revio hook install

    Pre-commit check. It doesn't block commits by default, and it keeps any hook you already have.

  5. Task 10

    Publish to npm

    Check the package name, build, test the packed tarball, release workflow. You do the first publish yourself.

DONE WHENnpm i -g it, run revio watch, and issues appear as you save.

You'll need: npm account.

Things most likely to bite, and covered by tests

  • Nothing to reviewA clean working tree prints "No changes to review." and never calls Gemini.
  • Deleted, renamed and binary filesSkipped quietly; they never crash the parser.
  • Gemini down, rate-limited or bad keyOne readable error line; the watcher keeps running.
  • Not a git repo"Revio needs a git repository." with exit code 2.
  • Duplicate webhooks and force-pushesThe same commit is never reviewed twice; falls back to the full PR diff when needed.
